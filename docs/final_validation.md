# Final Validation Runbook (Windows PowerShell)

This runbook avoids destructive operations by default. Run from the repository root. Never run `docker compose down -v` unless you deliberately intend to erase the local PostgreSQL volume and have a backup.

## 1. Configure environment

Run from the repository root. For a **fresh database with no existing volume**:

```powershell
$pgPassword = python -c "import secrets; print(secrets.token_hex(32))"
$jwtSecret = python -c "import secrets; print(secrets.token_hex(32))"
@("POSTGRES_DB=scm", "POSTGRES_USER=scm_admin", "POSTGRES_PASSWORD=$pgPassword", "JWT_SECRET=$jwtSecret", "GROQ_API_KEY=") | Set-Content -Encoding ascii .env
```

For an **existing database created by the old compose file**, preserve `POSTGRES_PASSWORD=scm_admin` in `.env` temporarily. Start only the database and rotate the actual role password before changing `.env` to the new value:

```powershell
# Ensure .env has POSTGRES_DB=scm, POSTGRES_USER=scm_admin, POSTGRES_PASSWORD=scm_admin and JWT_SECRET.
docker compose up -d db
$newPassword = python -c "import secrets; print(secrets.token_hex(32))"
docker compose exec -T db psql -U scm_admin -d scm -v ON_ERROR_STOP=1 -c "ALTER ROLE scm_admin WITH PASSWORD '$newPassword';"
$lines = @(Get-Content .env | Where-Object { $_ -notmatch '^POSTGRES_PASSWORD=' })
$lines += "POSTGRES_PASSWORD=$newPassword"
Set-Content -Encoding ascii .env $lines
docker compose up -d --build
```

The generated PostgreSQL password is hexadecimal so it is safe in the connection URL and in this SQL literal. `docker compose` does not read `backend/.env` automatically for variable interpolation. Never commit `.env`.

## 3. If the database already has a volume

Initialization scripts in `/docker-entrypoint-initdb.d` run only when PostgreSQL initializes an empty data directory. Apply the forward migration to an existing database without deleting its volume:

```powershell
Get-Content db\10_fixes.sql -Raw | docker compose exec -T db psql -U scm_admin -d scm -v ON_ERROR_STOP=1
```

Do not regenerate `db/07_seed.sql` unless you intend to prepare a new seed for a future clean database. Do not use `docker compose down -v` as a routine migration step.

## 9. Existing DB recovery

For a failed migration, keep the volume. Save the complete `psql` error, fix the migration, and re-run it after confirming the script is transactional and idempotent. If the database is not usable, back it up first with `pg_dump` before attempting recovery. Any destructive reset requires explicit team approval and a known backup.
